# Стратегия

> **Назначение:** твои **направления развития (R1, R2, …)** с бюджетами времени. Living document — обновляется при стратегической сессии (раз в неделю/месяц).

## Принципы

1. **R = направление, не задача**
   - Формулируй "освоить системное мышление", а не "прочитать книгу".
2. **Бюджет в часах в неделю**
   - Фиксируй реалистичный бюджет, а не желаемый.
3. **Ограничение по числу направлений**
   - Держи 5-7 направлений, больше сложно удерживать в управлении.
4. **Логика происхождения направлений**
   - Lifework (миссия) -> Dissatisfactions (что не так) -> R{N} (куда направляюсь).

## Макс-РП текущего этапа жизни

### 1) Макс-РП по 4 направлениям НЭП

#### _Направление 1 (например, диссертация)_
   - **Что управляется:** _опиши управляемый контур, а не общий лозунг ("делать больше")_.
   - **Недельный мини-РП:** _какой артефакт недели должен регулярно выходить_.
   - **Факт недели:** _какое внешне проверяемое подтверждение считается выполнением_.
   - **Причинный разбор:** _как weekly review отделяет рабочие решения от случайных совпадений_.
   - **Критерий готовности:** _какой необратимый или устойчивый результат считается завершением Макс-РП_.

#### _Направление 2 (например, деньги)_
   - **Что управляется:** _цепочка создания ценности/результата в этом контуре_.
   - **Недельный мини-РП:** _одно улучшение узкого места контура_.
   - **Факт недели:** _измеримый признак, что улучшение реально сработало_.
   - **Причинный разбор:** _какие правила остаются после проверки на фактах недели_.
   - **Критерий готовности:** _признак воспроизводимого результата без ручного героизма_.

#### _Направление 3 (например, здоровье)_
   - **Что управляется:** _система режима, нагрузки, восстановления и профилактики_.
   - **Недельный мини-РП:** _одно проверяемое изменение протокола_.
   - **Факт недели:** _наблюдаемые показатели в журнале фактов_.
   - **Причинный разбор:** _какие решения реально снижают срывы и стабилизируют контур_.
   - **Критерий готовности:** _устойчивость результата на длинной дистанции_.

#### _Направление 4 (например, школа/проект передачи)_
   - **Что управляется:** _воспроизводимая система ролей, программы и пути участника_.
   - **Недельный мини-РП:** _завершенный элемент системы (модуль, сессия, методическая единица)_.
   - **Факт недели:** _применение на реальных участниках + зафиксированная обратная связь_.
   - **Причинный разбор:** _какие форматы усиливают качество передачи и удержание_.
   - **Критерий готовности:** _система работает стабильно даже при снижении ручного участия основателя_.

### 2) Макс-РП по орг-управленческой компетенции

#### Орг-управленческая компетенция: операционная система прогресса 4 контуров
   - **Содержание компетенции:** _способность проектировать и удерживать цикл "план -> факт -> урок -> изменение правила"_.
   - **Форма реализации в макс-РП:** _недельный ритм, где в каждом контуре зафиксирован факт результата_.

#### Подсистема 1 - машинка мини-РП
   - **Граница контура:** _отвечает только за выпуск мини-РП, не за анализ причин и не за внедрение правил_.
   - **Управленческий цикл:** _роль -> метод -> `WorkPlan` -> факт артефакта недели_.
   - **Правило факта:** _план без проверяемого артефакта = незавершенный цикл_.
   - **Проверка на weekly review:** _фиксируется разрыв между планом и фактом, определяется узкое место_.
   - **Критерий готовности подсистемы:** _регулярный выпуск мини-РП в каждом контуре_.

#### Подсистема 2 - извлекатель уроков
   - **Граница контура:** _отвечает только за причинные выводы из фактов недели_.
   - **Цикл мышления:** _гипотеза -> следствия -> проверка на наблюдаемых данных_.
   - **Дисциплина причинности:** _корреляция не считается доказанным эффектом без проверки_.
   - **Форма результата:** _журнал уроков с метками "подтверждено/не подтверждено/проверить повторно"_.
   - **Критерий готовности подсистемы:** _регулярно производит проверенные уроки для перевода в правила_.

#### Подсистема 3 - внедрятель изменений
   - **Граница контура:** _отвечает только за перенос подтвержденных уроков в правила, ритмы и ограничения_.
   - **Перенос в действие:** _каждый принятый урок получает рабочую форму (изменение `WorkPlan`, ритуала, ограничения)_.
   - **Правило допуска:** _внедряются только изменения с ожидаемым эффектом и горизонтом проверки_.
   - **Проверка эффекта:** _изменение принимается после улучшения следующего мини-РП по качеству/скорости/воспроизводимости/цене усилия_.
   - **Критерий готовности подсистемы:** _правила обновляются регулярно и подтверждаются следующими циклами_.

## Программный горизонт

> Ритм планирования среднесрочных инициатив (6-12 мес). Параметризуемый — пилот выбирает методологию на L3.

```yaml
 cycle_duration: "_не задано_"          # заполнить вручную: 6w, 12w, 1q
 cycle_type: "time-boxed"              # альтернативы: rolling, milestone-based
```

**Текущий цикл:** _название / фокус_
**Следующий вех:** _что должно быть готово к концу цикла_

### 6-week cycles (Shape Up)

> Применять вместо недельного time-boxing, если:
> - РП >40h aggregate бюджет
> - Требует deep work (архитектура, исследование, дизайн)
> - Не зависит от еженедельных сигналов

Формат: 6 недель = 1 cycle. IWE-адаптация Shape Up (basecamp.com/shapeup):
1. **shape (до цикла)**
   - Формулировка проблемы и подхода.
2. **bet/pitch**
   - Решение, что берём в цикл.
3. **build (6 недель)**
   - Реализация.
4. **cool-down**
   - Интеграция, документация, планирование следующего цикла.

CyclePlan вместо WeekPlan на период цикла.

### Rolling OKR

> Адаптивный ритм пересмотра OKR — не по календарю, а по триггерам.

**Триггеры пересмотра:**
1. 2+ недели подряд miss по ключевой метрике.
2. Новый P0-сигнал меняет фокус.
3. Результат эксперимента инвалидирует текущую гипотезу.

**Формат пересмотра:**
1. Проверить: триггер устойчивый (не шум)?
2. Если да — создать draft `inbox/okr-review-YYYY-MM-DD.md` с предложением изменений (что меняем, на что, обоснование)
3. Уведомить пилота (Telegram): триггер + draft + запрос подтверждения
4. Только пилот (или агент по явному подтверждению пилота) — обновить `docs/Strategy.md` §«Квартальный фокус»
