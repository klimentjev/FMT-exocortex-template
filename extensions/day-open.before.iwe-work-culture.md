# Day Open — IWE work culture

Перед планированием дня применить рамку из `extensions/iwe-work-culture.md`.

## Проверка закрытия предыдущего дня (БЛОКИРУЮЩЕЕ)

Выполнять в шаге extensions **before**, **до** сборки плана на сегодня и **до** создания нового DayPlan.

1. Определить вчерашнюю дату `YYYY-MM-DD` (от реальной даты Day Open, не от system prompt).
2. Найти вчерашний DayPlan в `<governance-repo>/current/` или `<governance-repo>/archive/day-plans/` (`DayPlan YYYY-MM-DD.md`).
3. Считать предыдущий день **закрытым**, только если выполнены оба условия:
   - во frontmatter: `status: closed`;
   - в теле есть секция итогов (`## Итоги дня` или эквивалент с блоком «Завтра начать с»).
4. Если файла нет (пропуск дня / первый день) → не блокировать; зафиксировать в «Требует внимания»: «вчерашнего DayPlan нет».
5. Если файл есть, но день **не закрыт** (`status: active` / нет итогов / нет «Завтра начать с»):
   - **СТОП** полного Day Open;
   - сообщить пилоту: «Предыдущий день (YYYY-MM-DD) не закрыт»;
   - предложить сначала `/day-close` (или `/run-protocol day-close`) за вчера;
   - продолжать Day Open **только** после явного разрешения пилота («продолжай без Close» / «открой день») — тогда пункт остаётся в «Требует внимания».

## Проверки перед DayPlan

1. Пройти `Открытие дня`: кто пользователь сегодня по ведущим ролям и какие методы будут основными.
2. Спустить фокус по каскаду:
   - стратегия;
   - результаты месяца;
   - рабочие продукты недели;
   - блоки дня.
3. Для каждого значимого блока зафиксировать:
   - `WP`;
   - роль;
   - метод;
   - бюджет;
   - связь с результатом месяца, если блок крупный.
4. Если появляется работа больше 3 часов без связи с результатом месяца, явно пометить её как техдолг, отвлечение или предмет отдельного решения.

## Файл дневных заметок в inbox

При каждом запуске процедуры нового дня (skill `/day-open`, шаг extensions **before**) в каталоге `<governance-repo>/inbox/` должен быть файл заметок за текущую дату.

- **Шаблон имени:** `zametki-<день>-<месяц>-<год>` — три числа через дефис в порядке день, месяц, год (например `zametki-10-05-2026.md` для 10 мая 2026).
- **Действие агента:** если файла с таким именем за сегодняшнюю дату ещё нет — создать его (минимум: заголовок первого уровня с датой или пустой файл-заготовка). Если файл уже есть — не дублировать и не переименовывать.

Governance-репо: переменная окружения `$IWE_GOVERNANCE_REPO` (по умолчанию часто `DS-strategy`), корень рядом с рабочим пространством IWE.

## Даты из бортового журнала (стоп-отчеты) → Day Open

При каждом Day Open (шаг 2 / «Требует внимания»):

1. Прочитать активные стоп-отчеты в `<governance-repo>/current/08-logbook.md`.
2. Выписать обязательства с датами в горизонте **текущая неделя + 7 дней** (и явные дедлайны месяца, если ≤14 дней).
3. Перенести их в «Требует внимания» DayPlan **и** сверить с секцией «Даты из стоп-отчетов» в актуальном WeekPlan (добавить/обновить, не дублировать противоречиво).
4. SoT факта стоп-отчета остаётся в `current/08-logbook.md`; WeekPlan/DayPlan — только операционные напоминания.

## DayPlan каждый день (БЛОКИРУЮЩЕЕ)

Источник: `memory/day-rhythm-config.yaml → day_open.always_create_dayplan: true`.

1. **Шаг 7 Day Open не пропускать** — даже если сегодня `strategy_day`. Платформенный скилл может писать «DayPlan не создавать»; это правило **перекрывает** его для этого IWE.
2. **Всегда** создавать `current/DayPlan YYYY-MM-DD.md` + санитация `current/` (`extensions/day-open.after.md`) **до** записи.
3. `strategy_day` = дополнительный акцент (weekly review, стратегирование), а не замена DayPlan. План дня дублируется в DayPlan; в WeekPlan — только сводка или ссылка при необходимости.

## Трекер мини-РП на день

Источник: `DS-strategy/tools/mini-wp-week-tracker.html`.

1. При каждом Day Open вызвать skill `mini-wp-tracker` (project skill в `DS-strategy/.cursor/skills/mini-wp-tracker/`).
2. Skill выполняет:
   - проверку `DS-strategy/_my-pls/05-Strategy.md` на актуальность макс-РП и мини-РП;
   - обновление массивов `MAX_RP` и `MINI_RP` в трекере при расхождении;
   - проверку, что файл доступен пилоту (файл сам сбрасывает таблицу на шаблон дня при открытии в новую дату через `localStorage`).
3. При необходимости запустить шаблон дня вручную через кнопку «Шаблон дня».
